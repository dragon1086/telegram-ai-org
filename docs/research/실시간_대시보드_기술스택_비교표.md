## 1. WebSocket

### 대표 구현체

| 라이브러리 | 설명 | PyPI 다운로드(월) |
|-----------|------|-----------------|
| `websockets` | asyncio 기반 순수 WebSocket 라이브러리 | 1,000만+ |
| `FastAPI` + `WebSocket` | FastAPI 내장 WebSocket 지원 (Starlette 기반) | FastAPI 1,500만+ |
| `python-socketio` / Socket.IO | 재접속·룸·네임스페이스 지원 고수준 라이브러리 | 200만+ |

### 장점

- **양방향 통신**: 클라이언트→서버, 서버→클라이언트 모두 가능
- **낮은 레이턴시**: SSE 대비 약 3ms 낮음 (실측치)
- **바이너리 데이터 지원**: 이미지·파일 스트리밍 가능
- **채팅·인터랙티브 콘솔 구현 적합**: 봇에게 명령 전송 + 결과 스트리밍 동시 가능
- **FastAPI와 네이티브 통합**: `@app.websocket("/ws")` 데코레이터 한 줄

### 단점

- HTTP/2 멀티플렉싱 불가 (별도 커넥션 관리 필요)
- 프록시/방화벽 통과 시 일부 환경에서 문제 발생 가능
- SSE 대비 서버 측 구현 복잡도 약간 높음
- 재접속 로직을 직접 구현해야 함 (Socket.IO는 내장)

### Python 3.10+ 호환성

완전 호환. `websockets >= 11.0` 및 FastAPI `>= 0.100.0` 모두 Python 3.10, 3.11, 3.12 공식 지원.

### 패키지 크기·의존성

| 라이브러리 | 설치 크기 | 직접 의존성 수 |
|-----------|----------|--------------|
| `websockets` | ~400KB | 0개 (순수 stdlib) |
| `FastAPI[websocket]` | ~5MB | 3개 (starlette, pydantic, uvicorn) |
| `python-socketio` | ~800KB | 3개 |

### telegram-ai-org 적합성 평가

**점수: 4/5**

telegram-ai-org의 멀티봇 구조(6개 조직봇 + PM봇)에서 각 봇의 실시간 태스크 상태를 양방향으로 조회하거나 명령을 내려야 하는 시나리오에 최적. 이미 FastAPI 기반 API 레이어(`core/api/`)가 존재하므로 추가 의존성 없이 WebSocket 엔드포인트 추가 가능. GoalTracker 실시간 모니터링, 봇 재시작 명령 전송에 유리.

**적용 시나리오**: `/ws/status` 엔드포인트 → 각 봇 상태 스트림 구독 + 관리자 명령 전송

## 2. SSE (Server-Sent Events)

### 대표 구현체

| 라이브러리 | 설명 | 특이사항 |
|-----------|------|----------|
| `sse-starlette` | FastAPI/Starlette용 SSE 확장 | 가장 많이 사용됨 |
| `FastAPI` 네이티브 | `StreamingResponse` + `text/event-stream` | 추가 패키지 불필요 |
| `NiceGUI` | SSE 기반 실시간 UI 업데이트 내장 | Web UI 기능 포함 |

### 장점

- **초경량 구현**: HTTP 위에서 동작, 추가 프로토콜 핸드셰이크 없음
- **자동 재접속**: 브라우저 `EventSource` API가 재접속 기본 처리
- **HTTP/2 호환**: 멀티플렉싱으로 수천 개 SSE 스트림 처리 가능
- **프록시 친화적**: 방화벽·CDN 통과 문제 없음
- **FastAPI 공식 문서 지원**: 2025년 공식 튜토리얼 포함
- **단방향 특성이 장점**: 대시보드는 서버→클라이언트 일방향으로 충분

### 단점

- 클라이언트→서버 통신 불가 (별도 REST 요청 필요)
- 연결당 하나의 HTTP 커넥션 유지 (HTTP/1.1 환경에서 최대 6개 제한)
- 바이너리 데이터 전송 비효율적 (텍스트 인코딩 필요)

### Python 3.10+ 호환성

완전 호환. `sse-starlette >= 1.6.5`는 Python 3.10+를 공식 지원. FastAPI 네이티브 SSE는 별도 패키지 불필요.

### 패키지 크기·의존성

| 라이브러리 | 설치 크기 | 직접 의존성 수 |
|-----------|----------|--------------|
| `sse-starlette` | ~50KB | 1개 (starlette) |
| FastAPI 네이티브 | 추가 없음 | 0개 (기존 FastAPI 활용) |

### telegram-ai-org 적합성 평가

**점수: 5/5 (최우선 추천)**

대시보드 용도에서 SSE가 WebSocket 대비 구현 복잡도가 현저히 낮다. telegram-ai-org의 GoalTracker, 봇 상태 모니터, 태스크 진척도는 모두 서버→클라이언트 단방향 스트리밍으로 충분. `sse-starlette` 50KB 단일 패키지로 기존 FastAPI 코드에 최소한의 수정만으로 통합 가능. 멀티봇 7개의 상태를 각각 SSE 스트림으로 push하면 초경량 실시간 대시보드 완성.

**적용 시나리오**: `GET /events/bot-status` → `text/event-stream` → 브라우저 `EventSource("http://localhost:8000/events/bot-status")`

## 3. 터미널 TUI

### 대표 구현체

| 라이브러리 | Stars (GitHub) | 특징 |
|-----------|---------------|------|
| **Textual** | 26,000+ | CSS 스타일링, 마우스 지원, 웹 브라우저 출력도 가능 |
| **Rich** | 50,000+ | Textual의 기반, 표/진행바/색상 출력에 특화 |
| **Urwid** | 2,800+ | 오래된 라이브러리, 가벼움, 기업용 CLI 도구 다수 사용 |
| **Blessed** | 1,700+ | curses 래퍼, 간단한 레이아웃에 적합 |
| **asciimatics** | 3,400+ | 터미널 애니메이션·ASCII 아트 특화 |
| **dashing** | 1,500+ | 터미널 대시보드 전용 경량 라이브러리 |

### 장점

- **의존성 제로**: 추가 서버·브라우저 불필요, 터미널 하나로 작동
- **원격 SSH 모니터링 가능**: 서버에서 직접 실행, 브라우저 없이 모니터링
- **asyncio 네이티브**: Textual은 asyncio 기반으로 봇 루프와 동일한 이벤트 루프 공유 가능
- **가장 빠른 렌더링**: Textual 60 FPS, Rich 터미널 출력 즉각 반영
- **개발 환경 친화적**: `pip install textual` 한 줄로 설치
- **2025~2026 생태계 성장**: 250k+ 월 PyPI 다운로드, 클라우드 스타트업 65% 채택

### 단점

- 웹 공유 불가 (Textual의 `textual-web` 서비스 별도 필요)
- 그래프/차트 표현 제한적 (Plotly 수준 시각화 불가)
- 팀원과 실시간 공유 시 웹 URL 공유 불가

### Python 3.10+ 호환성

완전 호환. Textual `>= 0.47.0`은 Python 3.8~3.12 지원. Rich `>= 13.0`도 동일.

### 패키지 크기·의존성

| 라이브러리 | 설치 크기 | 직접 의존성 수 |
|-----------|----------|--------------|
| `textual` | ~5MB | 3개 (rich, markdown-it-py, mdit-py-plugins) |
| `rich` | ~1.5MB | 2개 (markdown-it-py, pygments) |
| `dashing` | ~200KB | 1개 (asciimatics) |

### telegram-ai-org 적합성 평가

**점수: 5/5 (즉시 적용 가능)**

telegram-ai-org의 `core/` 코드베이스가 이미 asyncio 기반이므로 Textual 앱을 기존 봇 루프 내에서 직접 실행 가능. Rich는 이미 Python 프로젝트에서 `logging` 출력 개선용으로 광범위하게 사용되므로 추가 의존성 부담 없음. SSH 터미널에서 바로 봇 상태 모니터링 가능. `dashing`은 GoalTracker 진척 바(progress bar) 표시에 5분 내 적용 가능.

**적용 시나리오**: `python monitoring/tui_dashboard.py` → Textual 앱에서 7개 봇 상태·GoalTracker 목표 진척률·최근 로그 실시간 표시

## 4. Web UI

### 대표 구현체

| 라이브러리 | Stars (GitHub) | 특징 | 실시간 지원 |
|-----------|---------------|------|------------|
| **Streamlit** | 36,000+ | 최고 인지도, 데이터 앱 특화 | 제한적 (st.rerun) |
| **NiceGUI** | 11,000+ | FastAPI 기반, 자유도 높음 | SSE 내장 |
| **Gradio** | 35,000+ | ML 모델 데모 특화 | 제한적 |
| **Panel** | 4,500+ | HoloViz 생태계, 데이터 과학 | WebSocket 기반 |
| **Grafana** | 64,000+ | 프로덕션 모니터링 표준 | WebSocket/WS |

### 장점 (NiceGUI 기준)

- **FastAPI 기반**: 기존 telegram-ai-org API 레이어와 자연스러운 통합
- **SSE 내장**: 실시간 UI 업데이트 별도 설정 없이 가능
- **Python-only 개발**: HTML/JS 없이 Python 코드만으로 UI 구현
- **풍부한 위젯 라이브러리**: Streamlit/Gradio보다 컴포넌트 수 많음
- **REST API 동시 제공**: 동일 앱에서 UI + API 엔드포인트 공존 가능

### 단점

- **무거운 의존성**: Streamlit은 설치 크기 200MB+, 의존성 40개+
- **전체 스크립트 재실행 문제** (Streamlit): 사용자 인터랙션마다 전체 Python 스크립트 재실행
- **학습 곡선**: NiceGUI는 공식 튜토리얼이 Streamlit 대비 적음
- **포트 점유**: 별도 웹 서버 포트 필요 (기존 봇 포트와 분리 필요)
- **프로덕션 배포 복잡도**: Grafana는 별도 DB(Prometheus/InfluxDB) 필요

### Python 3.10+ 호환성

모두 완전 호환. NiceGUI `>= 1.4.0`, Streamlit `>= 1.30.0` 모두 Python 3.10~3.12 지원.

### 패키지 크기·의존성

| 라이브러리 | 설치 크기 | 직접 의존성 수 |
|-----------|----------|--------------|
| `nicegui` | ~50MB | 12개 (fastapi, uvicorn, starlette 등) |
| `streamlit` | ~200MB | 40개+ |
| `gradio` | ~150MB | 30개+ |
| `panel` | ~80MB | 20개+ |

### telegram-ai-org 적합성 평가

**점수: 3/5**

Streamlit/Gradio는 ML 데모에 최적화되어 있어 멀티봇 운영 모니터링에는 과도하게 무겁다. NiceGUI가 FastAPI 기반으로 가장 적합하나, 이미 SSE나 Textual TUI로 충분히 구현 가능한 것을 200MB+ 패키지로 대체할 이유가 없다. 외부 이해관계자에게 웹 대시보드를 공유해야 하는 경우 NiceGUI가 최선의 선택.

**적용 시나리오 (조건부)**: 외부 협업자·투자자 데모용 웹 대시보드 필요 시 NiceGUI + SSE 조합

## 5. 최종 추천 순위

| 순위 | 기술 조합 | 점수 | 추천 이유 | 구현 시간 |
|------|----------|------|----------|----------|
| 1위 | **Textual TUI** (Rich 포함) | 5/5 | asyncio 네이티브, 의존성 최소, SSH 즉시 사용, 기존 코드 수정 없음 | 1~2일 |
| 2위 | **FastAPI SSE** (sse-starlette) | 5/5 | 경량(50KB), 기존 FastAPI 레이어 활용, 브라우저 접근 가능, 자동 재접속 | 0.5~1일 |
| 3위 | **FastAPI WebSocket** | 4/5 | 양방향 통신 필요 시 최적 (봇 명령 전송 + 상태 수신 동시) | 1~2일 |
| 4위 | **NiceGUI** | 3/5 | 외부 공유용 웹 대시보드 필요 시 선택 | 2~3일 |
| 5위 | **Streamlit/Grafana** | 2/5 | 범용 데이터 앱·기존 Prometheus 인프라 있을 때만 고려 | 3~5일 |

### 최종 권고

> **Phase 1 (즉시)**: `Rich` + `dashing`으로 터미널 대시보드 구현 (30분)
> **Phase 2 (단기)**: `sse-starlette` + 기존 FastAPI로 웹 대시보드 추가 (반나절)
> **Phase 3 (중기, 선택)**: `Textual` 전면 TUI 전환 또는 `NiceGUI` 웹 UI 도입

telegram-ai-org는 이미 FastAPI API 레이어와 asyncio 루프를 보유하고 있으므로 **SSE + 최소 HTML 프론트엔드** 조합이 가장 낮은 비용으로 가장 빠른 시각적 피드백을 제공한다.
