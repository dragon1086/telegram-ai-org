# 만화·캐릭터 컨셉 대시보드 레퍼런스 리포트
> 조사일: 2026-03-31 | telegram-ai-org 멀티봇 캐릭터화 UI 패턴 조사

---

## 핵심 인사이트

### 인사이트 1: AI 에이전트 UI의 "페르소나화" 트렌드 가속

2025년 기준 AI 에이전트 UI 디자인의 핵심 트렌드는 **에이전트를 단순 도구(tool)가 아닌 캐릭터(character)로 표현**하는 방향이다. Slack의 2025년 기업 AI 설계 조사에서 "톤 불일치(tone mismatch)"가 AI 기능 거부의 주요 원인으로 꼽혔다. 이는 캐릭터 설계가 기능성만큼 중요하다는 것을 시사한다.

### 인사이트 2: 감정 상태 표시는 신뢰도를 높인다

챗봇 UI 연구에 따르면 아바타에 감정 상태(기쁨/처리중/에러)를 시각적으로 표현하면 사용자의 신뢰도와 참여도가 높아진다. 단순한 상태 표시기(녹색/빨간색)보다 캐릭터 표정 변화가 더 직관적인 시스템 상태 피드백을 제공한다.

### 인사이트 3: 터미널 환경에서도 ASCII 아트로 캐릭터화 가능

`asciimatics`, `Rich`, `Textual` 등의 라이브러리를 조합하면 터미널에서도 캐릭터 아바타, 감정 표정, 애니메이션 상태 표시가 구현 가능하다. Live2D 수준의 정교함은 불가하나 ASCII 아트 기반 캐릭터 표현은 봇 개성화에 충분히 효과적이다.

### 인사이트 4: Rive 기반 인터랙티브 마스코트가 2025년 웹 UI 표준으로 부상

앱 마스코트를 타임라인 애니메이션이 아닌 **애플리케이션 상태(state)에 연동된 반응형 시스템**으로 설계하는 패턴이 2025년 표준으로 자리잡고 있다. 이 패턴을 telegram-ai-org 봇 아바타에 적용하면 각 봇의 실행 상태(idle/running/error)가 자동으로 캐릭터 표정에 반영된다.

### 인사이트 5: 조직별 고유 캐릭터가 팀 정체성 강화

telegram-ai-org처럼 6개 조직봇이 협업하는 구조에서 각 봇에 고유 캐릭터 아바타를 부여하면 대시보드에서 어떤 봇이 어떤 작업을 수행 중인지 즉각적으로 식별 가능하다. 이는 중국 디지털 어시스턴트 생태계(WeChat 기반 브랜드 마스코트)에서 이미 검증된 패턴이다.

## 디자인 패턴 정리

| 패턴명 | 설명 | 구현 방법 | 적용 예시 |
|--------|------|----------|----------|
| **감정 상태 매핑** | 봇/에이전트 실행 상태를 감정 표현에 1:1 대응 | 상태 enum → 이모지/아이콘/ASCII 아트 룩업 테이블 | `IDLE=😴`, `RUNNING=💻`, `ERROR=😰`, `SUCCESS=🎉` |
| **캐릭터 카드 그리드** | 각 봇을 독립 카드(아바타+이름+상태+태스크)로 표현 | CSS Grid 또는 Textual Grid 레이아웃 | 7개 봇 카드를 3×3 그리드로 배치 |
| **스플릿 스크린 모니터** | 좌=봇 상태 패널, 우=선택 봇 상세 로그 | 반응형 2-컬럼 레이아웃 | Textual Horizontal/NiceGUI split |
| **상태 머신 아바타** | 봇 상태 변수가 아바타 애니메이션을 직접 구동 | Rive 상태 머신 또는 CSS 애니메이션 | 봇 Running 상태 시 아바타 눈 깜빡임 루프 |
| **타이핑 인디케이터** | 봇이 처리 중일 때 "..." 또는 스피너 표시 | asyncio 상태 변수 → UI 반응형 업데이트 | Rich `Progress` 바 또는 Textual `LoadingIndicator` |
| **마스코트 알림 버블** | 에러/경고 시 마스코트 말풍선으로 알림 | 상태 감지 → Toast/Notification UI 트리거 | `봇이 에러를 만났어요! 😱` 말풍선 팝업 |
| **조직별 색상 코딩** | 각 조직봇에 고유 색상 할당 | CSS 변수 또는 Rich 색상 팔레트 | 개발실=파랑, 운영실=초록, 기획실=보라 등 |
| **진척률 애니메이션** | GoalTracker 목표 진행률을 시각적 막대로 표현 | Rich/Textual ProgressBar + 퍼센트 레이블 | G-aiorg_pm_bot-007: `████████░░ 80%` |

## telegram-ai-org 구현 우선순위

| 순위 | 패턴 | 기대 효과 | 구현 난이도 | 소요 시간 |
|------|------|----------|------------|----------|
| 1 | **감정 상태 매핑** (이모지 기반) | 봇 상태 즉각 인지, 터미널/웹 모두 적용 가능 | 하 | 2~4시간 |
| 2 | **캐릭터 카드 그리드** | 7개 봇 한눈에 파악, 시각적 명확성 향상 | 하~중 | 0.5~1일 |
| 3 | **타이핑 인디케이터** | 봇 처리 중 상태 명확히 전달, 대기 경험 개선 | 하 | 1~2시간 |
| 4 | **진척률 애니메이션** | GoalTracker 목표 진행률 시각화, 성취감 증대 | 하 | 2~4시간 |
| 5 | **스플릿 스크린 모니터** | 운영 효율성 향상, 봇 디버깅 시간 단축 | 중 | 1~2일 |
| 6 | **마스코트 알림 버블** | 에러 알림 가시성 향상, 즉각 대응 유도 | 중 | 1일 |
| 7 | **조직별 색상 코딩** | 조직 식별 속도 향상, 브랜드 정체성 강화 | 하 | 1~2시간 |
| 8 | **상태 머신 아바타** (Rive) | 몰입감 높은 캐릭터 경험, 데모 임팩트 | 상 | 1~2주 |

### 단계별 로드맵

**Phase 1 (즉시, 1~2일)**: 감정 상태 이모지 + 진척률 바 + 캐릭터 카드 그리드
- 기존 `monitoring/` 디렉토리에 `bot_status_display.py` 추가 (Rich 기반)
- 각 봇 상태를 이모지와 함께 터미널 표 출력

**Phase 2 (단기, 1주)**: SSE 기반 웹 대시보드 + 스플릿 스크린 레이아웃
- `sse-starlette` 추가 → 봇 상태 SSE 스트림
- 최소 HTML 프론트엔드에 캐릭터 카드 그리드 + 로그 패널 구현

**Phase 3 (중기, 2~4주)**: Rive/Live2D 기반 인터랙티브 마스코트 (선택)
- 데모/발표 목적의 고품질 캐릭터 대시보드
- 오픈소스 공개 시 프로젝트 인지도 향상 효과
