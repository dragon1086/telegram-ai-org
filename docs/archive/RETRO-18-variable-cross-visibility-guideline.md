## 2. 핵심 개념 정의

### 변수 교차 (Variable Cross)

두 개 이상의 독립 변수가 **동시에 변화**할 때 발생하는 예측 불가 상호작용.

| 변수 A | 변수 B | 교차 효과 |
|--------|--------|-----------|
| infra_baseline_version | 실험 설계 변수 | 이상치 원인 이분 불가 |
| 폰트 | 테마 | 렌더링 차이 증폭 |
| 코드 변경 | 인프라 변경 | 오류 원인 모호 |
| 모델 버전 | 조사 시점 | 리서치 결론 재현 불가 |

### 가시화 (Visibility)

설계 단계에서 **어떤 변수가 함께 변화할 수 있는가**를 명시적으로 매핑하여, 교차 발생 시 즉시 원인을 추적할 수 있는 구조.

---

## 3. 적용 시점

| 단계 | 적용 내용 | 책임 부서 |
|------|-----------|-----------|
| **설계 단계** | 변수 목록 식별 + 교차 가능성 매트릭스 작성 | 기획실 (요구사항 정의 시) |
| **구현 단계** | 변수 변경 시 교차 영향 체크리스트 실행 | 개발실 (코드/인프라 변경 시) |
| **테스트 단계** | 교차 조합 E2E 검증 자동화 | 개발실/디자인실 |
| **배포 단계** | pre-flight에서 교차 변수 상태 로그 삽입 | 운영실 |
| **운영 단계** | 이상치 발생 시 교차 변수 이분 트리 실행 | 기획실 + 운영실 |

> **핵심 원칙**: 교차 매트릭스는 **설계 단계에서** 반드시 완성. 구현 단계에서 소급 작성 금지.

## 4. 전사 공통 변수 교차 매트릭스 작성 가이드

### 4-A. 식별 대상 변수 유형

| 유형 | 예시 | 가시화 방식 |
|------|------|-------------|
| **인프라 변수** | infra_baseline_version, timeout, env | infra-baseline.yaml |
| **디자인 변수** | 뷰포트, 폰트, 테마 | design-baseline.yaml (RETRO-17 참조) |
| **모델/데이터 변수** | LLM 버전, 데이터 시점 | research_context.yaml |
| **실험 변수** | A/B 그룹, 피처 플래그 | experiment_log.yaml |
| **코드 변수** | 모듈 버전, API 스펙 | CHANGELOG / semver |

### 4-B. 교차 매트릭스 작성 형식

신규 기능/변경 사항 설계 시 아래 템플릿을 사용한다.

```yaml
# docs/cross_variable_matrix/{feature-name}.yaml
feature: "기능명"
created_at: "YYYY-MM-DD"
variables:
  - name: "변수A"
    type: "infra | design | model | experiment | code"
    change_frequency: "high | medium | low"
    current_value: "v1.2.0"

cross_combinations:
  - var_a: "변수A"
    var_b: "변수B"
    risk_level: "high | medium | low"
    effect: "교차 시 발생 가능한 현상"
    detection: "감지 방법"
    owner: "담당 부서"
```

### 4-C. 위험도 판단 기준

| 위험도 | 기준 | 필수 조치 |
|--------|------|-----------|
| 🔴 High | 두 변수 모두 change_frequency=high | 설계 단계 교차 검증 필수, CI 자동 체크 |
| 🟡 Medium | 한 변수 high + 한 변수 medium | 구현 전 체크리스트 실행 |
| 🟢 Low | 둘 다 low | 모니터링만, 사전 검증 선택 |
