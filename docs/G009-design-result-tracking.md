# G009 장기목표 결과 추적 화면 디자인 문서

**목표 ID**: G-aiorg_pm_bot-009
**문서 버전**: v1.0
**작성일**: 2026-04-01
**상태**: 설계 완료

---

## 개요

G009는 `max_iterations_reached` 상태로 강제 종료된 장기목표입니다. 이 문서는 해당 결과를 사용자에게 명확하게 전달하고, 후속 액션을 유도하는 3-Phase UI/UX 설계를 다룹니다. WCAG 2.1 AA 기준을 준수하며 텔레그램 메시지 UI 패턴을 따릅니다.

---

## Phase 1: 사용자 분석

### 1.1 페르소나 분석

| 페르소나명 | 역할 | 핵심 Pain Point | 요구 정보 | 설계 처방 |
|-----------|------|----------------|-----------|----------|
| PM Rocky | 의사결정자 | 목표 미달성 원인을 빠르게 파악하고 재계획 여부를 결정해야 함 | 달성률, 강제종료 사유, 이터레이션 초과 맥락, 후속 액션 옵션 | 상태 요약 카드를 첫 화면에 배치, 재등록/아카이브 원클릭 버튼 제공 |
| 팀 리더 | 실행 책임자 | 취소된 서브태스크 19개 중 어느 것이 블로커였는지 불명확함 | KR별 달성 상태, 서브태스크 취소 사유, 실질 산출물 목록 | 드릴다운 화면에서 KR-서브태스크 계층 구조 시각화, 취소 사유 레이블 표시 |
| 외부 스테이크홀더 | 결과 수신자 | 기술 맥락 없이 "실패"라는 인상만 남을 위험 | 간결한 상태 요약, 다음 단계 계획, 진행 중 산출물 존재 여부 | 기술 용어 제거, "강제종료" 대신 "이터레이션 한도 도달" 표현, 후속 계획 명시 |

### 1.2 핵심 사용 시나리오

#### 시나리오 1: G009 최종 결과 확인

```
트리거: PM Rocky가 아침 목표 리포트를 수신
행동 흐름:
  1. 텔레그램 알림 수신 → 목표 상태 요약 메시지 확인
  2. G009 항목에서 🔴 강제종료 배지 인지
  3. 달성률 0%, 이터레이션 11/10 수치 확인
  4. "상세 보기" 버튼 탭하여 드릴다운 진입

성공 조건: 30초 이내에 목표 상태와 종료 사유를 파악
실패 위험: 수치 과부하로 인한 스캔 실패 → 핵심 3개 수치만 첫 화면 노출로 대응
```

#### 시나리오 2: 미달성 원인 분석

```
트리거: 팀 리더가 취소 처리된 서브태스크 원인 파악 필요
행동 흐름:
  1. 상세 분석 화면 진입
  2. KR 목록에서 0/2 달성 현황 확인
  3. 서브태스크 섹션에서 cancelled 19개 목록 스캔
  4. 리서치실 참조 자료 3개 링크 확인 (유일한 실질 산출물)
  5. "원인분석" 버튼 탭 → 자동 분석 요청 트리거

성공 조건: 블로킹 요인 식별 및 재계획 근거 데이터 확보
실패 위험: 19개 취소 항목의 시각적 노이즈 → 요약 카운터 + 접이식 목록으로 대응
```

#### 시나리오 3: 후속 액션 결정

```
트리거: PM Rocky가 G009 처리 방향을 결정해야 함
행동 흐름:
  1. 후속 액션 패널에서 3개 옵션 확인: [재등록] [아카이브] [원인분석]
  2. 각 옵션의 결과 프리뷰 확인 (탭 시 확인 다이얼로그)
  3. 선택 후 확인 메시지 수신
  4. GoalTracker 상태 업데이트 완료 알림 수신

성공 조건: 3탭 이내 액션 완료, 실수 방지 확인 단계 통과
실패 위험: 실수로 아카이브 처리 → 비가역적 액션에 확인 다이얼로그 필수
```

- 목표 상태: `max_iterations_reached` (강제종료)
- 달성률: KR 0/2 (0%)
- 이터레이션 초과: 11/10
- 종료 시각: 2026-04-01 05:35 KST
- 후속 액션 버튼 (재등록 / 아카이브 / 원인분석)

**2사분면 (중요 + 긴급도 낮음) — 즉시 표시**
- confidence 값: 0.0
- 목표명 및 ID
- 서브태스크 취소 총계: 19개

**3사분면 (긴급 + 중요도 낮음) — 세부 조회 시 표시**

**4사분면 (중요도 낮음 + 긴급도 낮음) — 세부 조회 시 표시**

| 미달성 / 경고 | 🟡 | `#F57C00` | Orange 700 | 3.1:1 | AA (Large text) |
| 취소된 서브태스크 | ⚫ | `#757575` | Grey 600 | 4.6:1 | AA ✅ |
| 완료 / 성공 | ✅ | `#388E3C` | Green 700 | 5.1:1 | AA ✅ |
| 진행중 | 🔄 | `#1976D2` | Blue 700 | 4.5:1 | AA ✅ |
| 정보 / 중립 | ℹ️ | `#0288D1` | Light Blue 700 | 4.6:1 | AA ✅ |

**아이콘-색상 매핑 원칙**
- 모든 상태는 아이콘(이모지) + 텍스트 레이블을 동시 표시 (색맹 사용자 대응)
- 색상 단독으로 정보를 전달하지 않음 (WCAG 1.4.1 준수)
- 강제종료는 🔴 + "강제종료" 텍스트, 미달성은 ❌ + "미달성" 텍스트로 이중 표현

**진행바 표현 규칙**
```
달성 없음 (0%):   ░░░░░░░░░░░░░░░░░░░░  (빈 블록 20개)
50% 달성:         ██████████░░░░░░░░░░  (채움 10 + 빈 10)
100% 달성:        ████████████████████  (채움 20개)
한도 초과:        ████████████████████+ (채움 20개 + + 기호)
```

### 3.3 접근성 체크리스트

| # | 항목 | 구현 방법 | 충족 여부 |
|---|------|----------|----------|
| 1 | **색맹 대응** (색상+아이콘 이중 표현) | 모든 상태에 이모지 아이콘 + 텍스트 레이블 병행. 색상 단독 정보 전달 없음. (WCAG 1.4.1) | ✅ |
| 2 | **스크린리더 호환 텍스트** | 이모지에 의존하지 않고 텍스트 설명 항상 포함. 상태명을 텍스트로 명시. (WCAG 1.1.1) | ✅ |
| 3 | **터치 타겟 최소 44px** | 인라인 버튼은 텔레그램 기본 최소 44x44px 터치 영역 보장. 버튼 텍스트 충분한 패딩 확보. (WCAG 2.5.5) | ✅ |
| 4 | **대비율 AA 기준 충족** | 본문 텍스트 4.5:1 이상, 대형 텍스트 3:1 이상 확보. 강제종료 5.7:1, 취소 4.6:1 모두 AA 충족. (WCAG 1.4.3) | ✅ |
| 5 | **오류 상태 명확한 텍스트 레이블** | "강제종료", "미달성", "한도 초과" 등 오류/경고 상태를 이모지에 의존하지 않고 텍스트로 명확히 표시. 사유 설명 문장 포함. (WCAG 3.3.1) | ✅ |

### 3.4 반응형 고려사항 (텔레그램 환경)

**텍스트 길이 제한**
- 메시지 본문: 4096자 이내
- 인라인 버튼 텍스트: 64자 이내
- 버튼 행당 최대 8개 (실제 권장 3개 이내)

**모바일 최적화**
- 버튼 2열 레이아웃 (재등록 + 아카이브) + 1열 (원인분석) 배치
- 중요 정보는 메시지 상단에 배치 (스크롤 없이 확인)
- 숫자 데이터는 굵게 (`*bold*`) 강조하여 스캔 용이성 확보

**네트워크 지연 대응**
- 버튼 탭 후 즉시 로딩 상태 표시 ("🔄 처리 중...")
- 원인분석 등 장시간 작업은 예상 소요 시간 명시

## 설계 결정 근거

1. **요약-상세 2단계 구조**: 의사결정자(PM Rocky)가 30초 이내 핵심 파악 → 팀 리더가 세부 분석 필요 시 드릴다운 진입하는 역할별 정보 소비 패턴을 반영
2. **비가역적 액션 경고**: 아카이브 버튼에 ⚠️ 경고 + 확인 다이얼로그 추가로 실수 방지 (WCAG 3.3.4 오류 방지)
3. **취소 목록 접이식 표시**: 19개 취소 항목의 시각적 노이즈를 줄이면서 필요 시 전체 조회 가능하도록 점진적 공개 패턴 적용
4. **confidence 0.0 명시**: 신뢰도 수치를 상태 요약에 포함해 재등록 결정 시 기준 데이터로 활용 가능
