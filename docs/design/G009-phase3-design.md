## 1. 디자인 토큰 — 상태별 매핑

텔레그램은 CSS 색상을 직접 적용할 수 없으므로, `tokens.css`의 시맨틱 색상을 이모지·텍스트 패턴으로 변환한다.

### 상태별 디자인 토큰 매핑표

| 상태 코드 | tokens.css 참조 | 이모지 | 텍스트 레이블 | 설명 (한국어) | WCAG |
|----------|----------------|--------|--------------|--------------|------|
| `max_iterations_reached` | `--color-danger: #f85149` | 🔴 | **[STOPPED]** | **이터레이션 초과** | 1.4.1 ✅ |
| `completed` | `--color-success: #3fb950` | ✅ | **[DONE]** | **목표 달성** | 1.4.1 ✅ |
| `in_progress` | `--color-info: #58a6ff` | 🔵 | **[RUN]** | **진행 중** | 1.4.1 ✅ |
| `stagnated` | `--color-warning: #d29922` | 🟡 | **[WARN]** | **진행 정체** | 1.4.1 ✅ |
| `failed` | `--color-danger: #f85149` | ❌ | **[FAIL]** | **미달성** | 1.4.1 ✅ |
| `cancelled` | `--brand-text-muted: #8b949e` | ⚫ | **[VOID]** | **취소됨** | 1.4.1 ✅ |

### 보조 시각 요소 토큰

| 요소 | 텔레그램 표현 | 참조 토큰 |
|------|-------------|---------|
| 섹션 구분선 | `━━━━━━━━━━━━━━━━━━━━` | `--brand-border` 대응 |
| 서브섹션 구분 | `─ 섹션명 ──────────────` | `--brand-border-muted` 대응 |
| 강조 수치 | `` `수치` `` (인라인 코드) | `--engine-claude-light` 대응 |
| 경고 항목 | `⚠️  텍스트` | `--color-warning` 대응 |

| 미수신 항목 | `❌ 텍스트` | `--color-danger` 대응 |

### 프로그레스 바 토큰

```

초과 구간 (overflow):   ▌  —  --color-danger 대응
미달 구간 (empty):      ░  —  --brand-text-subtle 대응
```

## 4. 접근성 가이드 (WCAG 2.1 AA)

### 4.1 색상 의존 배제 (Success Criterion 1.4.1)

**원칙**: 텔레그램은 사용자 설정에 따라 다크/라이트 모드가 전환된다. 색상만으로 상태를 전달하면 안 된다.

| 위반 패턴 | 준수 패턴 |
|---------|---------|
| 빨간 텍스트로만 실패 표시 | `🔴 [STOPPED] 이터레이션 초과` |
| 녹색 텍스트로만 성공 표시 | `✅ [DONE] 목표 달성` |
| 노란 원으로만 경고 표시 | `🟡 [WARN] 진행 정체 · 텍스트 설명` |

**검증 방법**: 메시지에서 이모지를 모두 제거했을 때 상태를 텍스트만으로 구별 가능해야 한다.

```
이모지 제거 테스트:
  원본:  "🔴 [STOPPED] G009 · 이터레이션 초과 종료"
  제거:  "[STOPPED] G009 · 이터레이션 초과 종료"
  판단:  [STOPPED] 레이블만으로 상태 식별 가능 → PASS
```

---

### 4.2 텍스트 명도 대비 (Success Criterion 1.4.3)

텔레그램은 CSS를 허용하지 않으므로 **마크다운 강조**를 계층 구조 대용으로 사용한다.

| 텍스트 레이어 | 텔레그램 마크다운 | 시각 효과 | WCAG 대응 |
|-------------|----------------|---------|---------|
| P0 상태 배지 | `**🔴 [STOPPED]**` | 볼드 + 이모지 | 구조적 강조 |
| P1 핵심 수치 | `` `0/2 KR` `` | 인라인 코드 (배경 강조) | 시각 구별 |
| P2 종료 사유 | 일반 텍스트 + `•` 불릿 | 목록 구조 | 3.2.3 일관성 |
| P3 산출물 | 숫자 목록 + 들여쓰기 | 계층 구조 | 1.3.1 정보 구조 |
| P4 명령어 | `` `/goal new` `` | 인라인 코드 | 구별 강조 |

**명도 근거** (`tokens.css` WCAG AA 검증):
- `#e6edf3` on `#0d1117` → 대비 15.8:1 (AAA 통과)
- `#f85149` (danger) on `#0d1117` → 대비 4.5:1 (AA 경계 통과)

텔레그램 다크 배경(`#17212b` 기준) 대비:
- 볼드 텍스트: 시스템 기본색 → 다크 12~15:1 / 라이트 10~12:1 예상
- 인라인 코드: 배경색 강조로 추가 시각 계층 제공

### 4.3 일관된 내비게이션 (Success Criterion 3.2.3)

모든 GoalTracker 결과 메시지는 다음 섹션 순서를 고정한다.

```
고정 순서 (변경 금지):
  1. 헤더 (📊 GoalTracker 결과)
  2. P0: 상태 배지
  3. P1: 달성률 + 이터레이션
  4. P2: 종료 사유
  5. P3: 산출물 목록 (Level 0만)
  6. 타임라인 (Level 0만)
  7. P4: 후속 액션
  8. 푸터 (ℹ️ 안내 + 구분선)

근거: PM이 G009, G010, G011 결과를 연속으로 확인할 때
      동일 위치에서 같은 정보를 찾을 수 있어야 한다.
```

### 4.4 오류 식별 및 설명 (Success Criterion 3.3.1)

`max_iterations_reached` 같은 기술 코드는 반드시 설명을 병기한다.

| 기술 용어 | 병기 방법 | 예시 |
|---------|---------|-----|
| `max_iterations_reached` | 한국어 설명 + 수치 | `이터레이션 한도 초과 (11회 / 허용 10회)` |
| `confidence: 0.0` | 괄호 내 의미 설명 | `신뢰도 0.0 (달성 불확실)` |
| `KR` | 첫 등장 시 풀어쓰기 | `KR (핵심 결과 지표)` |
| `stagnated` | 한국어 레이블 병기 | `🟡 [WARN] 진행 정체` |

### 4.5 충분한 시간 (Success Criterion 2.2.1)

- GoalTracker 결과 메시지는 텔레그램 채팅 히스토리에 영구 보존된다.
- 자동 삭제 기능 적용 금지.
- 메시지에 `종료: 2026-04-01 05:35 KST` 형태로 타임스탬프 필수 포함.

---

### 4.6 스크린리더 고려 (텔레그램 접근성 API)

텔레그램은 스크린리더에 텍스트를 순차 전달한다. 이모지 설명이 자동으로 읽히므로 과도한 이모지 사용을 자제한다.

```
권장 이모지 밀도:
  섹션당 이모지 1~2개 (헤더 이모지 + 상태 이모지)
  연속 이모지 3개 이상 금지 (스크린리더 소음)

스크린리더 읽기 순서 예시:
  "📊 (차트막대이모지) GoalTracker 결과 리포트"
  "🔴 (빨간원이모지) STOPPED G009 이터레이션 초과 종료"
  → 이모지 설명 + 텍스트가 순서대로 읽혀 의미 전달 가능
```

## 6. 마크다운 렌더링 명세 (텔레그램 HTML 모드)

텔레그램 봇은 `parse_mode='HTML'` 또는 `parse_mode='MarkdownV2'`를 지원한다.

### MarkdownV2 기준 렌더링 명세

```
강조 텍스트:  **[STOPPED]**    → 볼드
인라인 코드:  `0/2 KR`         → 코드 블록 배경
이탤릭:       _설명텍스트_      → 기울임 (보조 정보)
취소선:       ~사용안함~        → 사용 금지 (혼란 유발)
코드블록:     ```코드```        → 산출물 경로에 사용 금지 (렌더링 문제)
```

### HTML 모드 기준 렌더링 명세

```html
<!-- 상태 배지 -->
🔴 <b>[STOPPED]</b> G009 · 이터레이션 초과 종료

<!-- 핵심 수치 -->
달성  ░░░░░░░░░░  <code>0/2 KR</code> (0%)

<!-- 명령어 -->
🔄 [A] 재등록  →  <code>/goal new "G009 이어서"</code>

<!-- 경고 항목 -->
⚠️  <i>리서치실 산출물 3개는 보존됩니다.</i>
```

### 특수문자 이스케이프 규칙 (MarkdownV2)

```
이스케이프 필요: _ * [ ] ( ) ~ ` > # + - = | { } . !
산출물 제목에 특수문자 포함 시 백슬래시 이스케이프 적용
예: "AIMesh 경량화·대시보드·오픈소스화" → 특수문자 없음, OK
    "v1.0 릴리즈" → "v1\.0 릴리즈" 처리 필요
```
