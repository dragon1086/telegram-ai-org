## 1. 설계 원칙

Phase 1 UX 리서치에서 도출된 핵심 인사이트를 와이어프레임에 반영한다.

| 원칙 | 내용 | Phase 1 근거 |
|------|------|-------------|
| **30초 파악 원칙** | P0~P2 정보를 스크롤 없이 한 화면에 표시 | PM 사용 시나리오 Step 1~5 |
| **모순 해소 원칙** | 달성률(KR)과 산출물 수를 별개 섹션으로 분리 | 인사이트 #2 |
| **기술 용어 병기** | `max_iterations_reached` → "이터레이션 한도 초과" | 인사이트 #3 |
| **부서 가시성** | 산출물 제출 부서 vs 미수신 부서 명시 | 인사이트 #4 |
| **마찰 제거** | 후속 액션을 명령어 추천으로 즉시 실행 가능 | 인사이트 #5 |
| **색상 독립** | 이모지 + 텍스트 레이블 조합, CSS/색상 의존 금지 | WCAG 1.4.1 |

## 2. View 1: 요약 카드 (Goal Summary Card)

**용도**: 텔레그램 알림 팝업에서 핵심 상태를 즉각 인식 (5초 목표)
**우선순위**: P0 (상태 배지) + P1 (달성률)

```
╔═══════════════════════════════════════╗
║  📊 GoalTracker 결과 리포트            ║
║  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ║
║                                       ║
║  🔴 [STOPPED] G009                    ║  ← P0: 상태 배지
║  이터레이션 한도 초과 종료             ║  ← P0: 상태 설명 (한국어)
║                                       ║
║  AIMesh 경량화·대시보드·오픈소스화     ║  ← 목표 제목
║  G-aiorg_pm_bot-009                   ║  ← 목표 ID (축약 표기)
║                                       ║
║  달성률  ░░░░░░░░░░  0/2 KR (0%)      ║  ← P1: 프로그레스 바
║  신뢰도  0.0 / 1.0                    ║  ← P1: confidence
║  반복    ██████████▌ 11/10 회 [초과]   ║  ← 이터레이션 카운터
║                                       ║
║  종료 사유: 이터레이션 한도 초과       ║  ← 핵심 종료 사유 1줄
║  (11회 실행 → 허용 한도 10회 초과)    ║
╚═══════════════════════════════════════╝
```

### 컴포넌트 명세 — View 1

| 요소 | 표현 방식 | WCAG 규칙 |
|------|----------|-----------|
| 상태 배지 | `🔴 [STOPPED]` — 이모지 + 대괄호 레이블 | 1.4.1 색상 독립 |
| 목표 ID | `G009` (축약) + 전체 ID 병기 | 3.1.3 언어 명확성 |
| 프로그레스 바 (KR) | `░░░░░░░░░░` 10칸 = 0% | 텍스트 기반 시각화 |
| 이터레이션 바 | `██████████▌` 초과 표시 + `[초과]` 레이블 | 1.4.1 색상 독립 |
| 종료 사유 | 기술 용어 + 괄호 내 한국어 설명 | 3.3.1 오류 식별 |

### 프로그레스 바 규칙

```
KR 달성률 (10칸 기준):
  0/2   = ░░░░░░░░░░  (0%)
  1/2   = █████░░░░░  (50%)
  2/2   = ██████████  (100%) ✅

이터레이션 (10칸 = 허용 한도):
  5/10  = █████░░░░░  (허용 범위)
  10/10 = ██████████  (한도 도달)
  11/10 = ██████████▌ [초과]  (초과 — '▌' 오버플로우 표시)
```

║  ┌──────────────────┬──────┬───────┐  ║
║  │ 핵심 결과 지표   │ 목표 │ 현황  │  ║
║  ├──────────────────┼──────┼───────┤  ║
║  │ KR1 AIMesh PRD  │  ✅  │  ❌   │  ║

║  └──────────────────┴──────┴───────┘  ║
║  → 0/2 KR 달성 | confidence: 0.0     ║
║                                       ║
║  [산출물 현황]                         ║  ← 산출물 섹션

║  ┌─────────────────────────────────┐  ║
║  │ [리서치실] 산출물 3개            │  ║
║  │  1. 경량화 대상 컴포넌트 분석표  │  ║

║  │     docs/research/...           │  ║
║  └─────────────────────────────────┘  ║
║  ⚠️  미수신 부서 (결과 없음)           ║
║  ┌─────────────────────────────────┐  ║
║  │  ❌ 기획실  — 결과 미수신        │  ║
║  │  ❌ 디자인실 — 결과 미수신       │  ║
║  │  ❌ 운영실  — 결과 미수신        │  ║
║  │  ❌ 개발실  — 결과 미수신        │  ║

║  [타임라인]                            ║  ← 타임라인

║  │                                   ║
║  ├ 중간   이터레이션 5 — 부분 진행    ║

### KR 달성 상태 테이블 명세

| 컬럼 | 내용 | 너비 |
|------|------|------|
| 핵심 결과 지표 | KR 이름 (20자 이내 축약) | 가변 |
| 목표 | 목표 존재 여부 `✅` | 고정 4칸 |
| 현황 | 달성 `✅` / 미달성 `❌` / 진행중 `⏳` | 고정 4칸 |

### 산출물 목록 표현 규칙

```
부서별 그룹화:
  [부서명] 산출물 N개
    N. 산출물 이름 (20자 이내)
       파일 경로 (축약)

미수신 부서:
  ❌ 부서명 — 결과 미수신

최대 표시:
  산출물: 각 부서 최대 3개 (초과 시 "외 N개")
  미수신 부서: 전체 표시 (생략 없음)
```

### 타임라인 컴포넌트 규칙

```
시작: ○ (빈 원)
중간: ├ (분기점)
종료: ● (채운 원)
  — STOPPED 상태: ● 표시 + 종료 사유 병기
  — COMPLETED 상태: ● ✅ 표시
```

## 4. View 3: 후속 액션 패널 (Action Panel)

**용도**: 결과 확인 후 PM의 다음 행동을 즉시 유도
**우선순위**: P4 (후속 액션)

```
╔═══════════════════════════════════════╗
║  ⚡ 후속 액션                          ║
║  ─────────────────────────────────── ║
║                                       ║
║  G009 종료 상태: 🔴 이터레이션 초과   ║
║  권장 액션을 선택하세요:               ║
║                                       ║
║  ┌─────────────────────────────────┐  ║
║  │  🔄 [A] 목표 재등록 (재시도)     │  ║  ← 주요 액션
║  │  → /goal new "G009 이어서 진행"  │  ║
║  │     기존 산출물 컨텍스트 유지    │  ║
║  └─────────────────────────────────┘  ║
║                                       ║
║  ┌─────────────────────────────────┐  ║
║  │  🔍 [B] 원인 분석               │  ║  ← 보조 액션
║  │  → /goal analyze G009           │  ║
║  │     이터레이션 초과 원인 상세 조회│  ║
║  └─────────────────────────────────┘  ║
║                                       ║
║  ┌─────────────────────────────────┐  ║
║  │  📦 [C] 아카이브 (현 상태 보존) │  ║  ← 보존 액션
║  │  → /goal archive G009           │  ║
║  │     산출물 보존, 추가 실행 없음  │  ║
║  └─────────────────────────────────┘  ║
║                                       ║
║  ℹ️  산출물 3개는 archive 시에도 유지  ║
╚═══════════════════════════════════════╝
```

### 액션 버튼 컴포넌트 명세

| 액션 | 이모지 | 레이블 | 명령어 | 상황 |
|------|--------|--------|--------|------|
| 재등록 | 🔄 | [A] 목표 재등록 | `/goal new "[설명]"` | 목표를 이어서 진행하고 싶을 때 |
| 원인 분석 | 🔍 | [B] 원인 분석 | `/goal analyze G009` | 실패 원인을 파악하고 싶을 때 |
| 아카이브 | 📦 | [C] 아카이브 | `/goal archive G009` | 현 상태 보존, 재시도 안 할 때 |

### 조건부 액션 표시 규칙

```
상태별 기본 권장 액션:
  max_iterations_reached  → [A] 재등록 (주요) + [B] 원인 분석 + [C] 아카이브
  failed                  → [B] 원인 분석 (주요) + [A] 재등록 + [C] 아카이브
  completed               → [산출물 검토] (주요) → 후속 목표 설정
  stagnated               → [B] 원인 분석 (주요) + [A] 재등록
```

## 6. 상태별 배지 시스템 와이어프레임

모든 GoalTracker 결과 메시지에 공통 적용되는 상태 배지 컴포넌트.

```
상태 배지 컴포넌트:
┌────────────────────────────────────────┐
│  [이모지] [레이블]  [상태 설명]         │
└────────────────────────────────────────┘

5가지 상태 매핑:
┌─────────────────────┬─────────┬──────────────────────┐
│ 상태 코드           │ 배지    │ 설명 텍스트           │
├─────────────────────┼─────────┼──────────────────────┤
│ completed           │ ✅ [OK] │ 목표 달성             │
│ max_iterations_reached│🔴[STOP]│ 이터레이션 한도 초과 │
│ stagnated           │ 🟡[WARN]│ 진행 정체 후 중단     │
│ in_progress         │ 🔵[RUN] │ 진행 중               │
│ cancelled           │ ⚫[VOID]│ 수동 취소             │
│ failed              │ ❌[FAIL]│ 목표 미달성           │
└─────────────────────┴─────────┴──────────────────────┘
```

### 배지 적용 규칙

```
규칙 1: 이모지는 반드시 텍스트 레이블과 병행 (WCAG 1.4.1)
규칙 2: 레이블은 대괄호로 감싸 스캔 가능성 향상 [STOP]
규칙 3: 상태 설명은 한국어로 병기 (WCAG 3.1.3)
규칙 4: 배지는 항상 메시지 첫 번째 정보 항목 (알림 팝업 가시성)
```

## 7. 반응형 축약 규칙

텔레그램 메시지가 너무 길어질 경우 적용하는 축약 규칙.

```
축약 단계:
  Level 0 (기본): P0 + P1 + P2 + P3 + 타임라인 + P4 — 전체 표시
  Level 1 (요약): P0 + P1 + P2 + P4 — 산출물 목록 생략
  Level 2 (최소): P0 + P1 + P4 — 핵심만 표시

트리거:
  산출물 5개 초과 → Level 1 자동 전환
  목표 제목 20자 초과 → 20자 + "..." 처리
  미수신 부서 5개 초과 → "외 N개 부서 미수신" 축약
```

## 8. 컴포넌트 명세

### C-001: StatusBadge (상태 배지)

```
입력: status (string), goal_id (string)
출력: "{이모지} [{레이블}] {goal_id} · {설명}"

예시:
  input:  status="max_iterations_reached", goal_id="G009"
  output: "🔴 [STOPPED] G009 · 이터레이션 한도 초과"
```

### C-002: ProgressBar (프로그레스 바)

```
입력: current (int), total (int), overflow_allowed (bool)
출력: "{바 10칸} {current}/{total} ({퍼센트}%)"

규칙:
  - 10칸 기준: 1칸 = 10%
  - '█' 채운 칸, '░' 빈 칸
  - overflow_allowed=True: current > total 시 '▌' 추가 + "[초과]" 레이블

예시:
  input:  current=11, total=10, overflow_allowed=True
  output: "██████████▌ 11/10 [초과]"

  input:  current=0, total=2, overflow_allowed=False
  output: "░░░░░░░░░░ 0/2 KR (0%)"
```

### C-003: DeliverableList (산출물 목록)

```
입력: deliverables (list[{dept, name, path}]), max_per_dept (int=3)
출력: 부서별 그룹화 텍스트 블록

규칙:
  - 부서별 그룹화: "[부서명] N개"
  - 각 산출물: "  N. {이름}" + "     {경로 축약}"
  - max_per_dept 초과: "  외 N개" 표기
```

### C-004: ActionPanel (후속 액션 패널)

```
입력: status (string), goal_id (string)
출력: 3개 액션 블록

상태별 주요 액션:
  max_iterations_reached → 🔄 [A] 재등록 (강조)
  failed                 → 🔍 [B] 원인 분석 (강조)
  completed              → 📋 [산출물 검토] (강조)
```

### C-005: Timeline (타임라인)

```
입력: started_at (datetime), ended_at (datetime), status (string)
출력: 타임라인 텍스트 블록

포맷:
  ○ {started_at}  시작
  ● {ended_at}  종료 ({종료 설명})
```
